# 手機使用檢視與改善

日期：2026-11-03。針對本機目前版本檢視總覽、現金、持倉、新增交易、交易紀錄與數字輸入。使用合成資料，沒有連線修改正式帳務。

## 已完成的改善

| 問題 | 調整後的行為 |
|---|---|
| 紀錄頁篩選欄位直排，交易內容太晚出現 | 手機改為兩欄；載入更多移到列表下方 |
| 隱藏金額的浮動按鈕會擋住交易操作 | 手機移到頁首，桌面保留原位置 |
| 部分操作太小，文字輸入容易讓手機放大畫面 | 手機一般按鈕至少 44px、底部導覽至少 48px；輸入欄位 16px |
| 股數與價格輸入需要更多捲動 | 手機並排，買賣方向獨立一列；代號關閉自動更正 |
| 矮螢幕的自訂鍵盤可能超出畫面 | 輸入面板限制高度並支援內部捲動；關閉按鈕加大 |
| 填表、垂直捲動時可能觸發左右換頁 | 排除表單、按鈕等互動區域；明確垂直捲動後取消該次換頁判定；保留螢幕邊緣手勢 |
| 現金摘要占用太多高度，校正用途不清楚 | 次要金額並排；明確標示「帳戶餘額校正」與使用說明 |
| 金額每次從零動畫到實際值，短暫顯示錯誤金額並持續更新畫面 | 直接顯示實際金額，移除 1.4 秒逐幀計數 |
| 底部導覽與手機安全區可能遮擋內容 | 補上安全區設定與內容底部間距 |

## 驗證結果

- 前端正式建置成功，前端測試 11 項通過，差異格式檢查通過。
- 390 × 844：交易紀錄輸入與選單字級皆 16px，頁面沒有水平溢出；股數與價格並排。
- 320 × 568：紀錄、現金繳款展開、持倉與總覽沒有整頁水平溢出。
- 390 × 400：數字輸入面板留在畫面範圍內，可捲動並完成輸入 1.5，值有保留。
- 信用卡繳款保留來源現金帳戶、全部繳清／指定金額入口。本次沒有送出繳款。

以上為本機瀏覽器尺寸模擬，尚未以實體 iPhone Safari／Android Chrome 驗證原生鍵盤、瀏海與系統返回手勢。沒有正式站 API 延遲或手機 CPU／網路效能量測；移除計數動畫屬於程式路徑改善，不能據此宣稱整站載入快了多少。

## 後續優先方向

1. 若紀錄查詢頻率較低，可進一步把進階篩選收合，預設先呈現交易。
2. 總覽仍有較多資產資訊；可依實際使用習慣，將最常看的金額保留在第一屏，其餘預設收合。
3. 正式站效能需另量測慢速行動網路、長交易列表與真實 API 回應，再決定是否調整查詢或快取。
