## 三、實際會看到的差異（共 4 項）

### 1. 登入畫面（新增）

進站要先輸入密碼。這是 A1 的必然結果，不是重構造成的。

### 2. 刷新按鈕文字：「背景更新中」→「更新中…」

總覽頁與持倉頁各一處。

原因是行為真的變了：以前按下去是丟一個背景任務就馬上回傳（而且在 serverless 上可能中途被砍掉），
現在是同步等後端抓完價、重算完才回來。繼續叫「背景更新」會名實不符。

**如果你想改回原本的字，跟我說一聲就好。**

### 3. 持倉頁點進個股的「買入紀錄」數字會變

只影響**有發生過股票分割的標的**（例如 MUU）。

原本前端自己算一份 FIFO，完全不知道分割存在，所以分割後的股數與均價是錯的。
現在改由後端計算，並套用 `corporate_actions` 表裡登記的分割事件。

沒有分割的標的，數字完全不變（有 12 個測試守著「明細加總 == `calc_fifo` 總數」）。

### 4. 資料更新時機

| 情境 | 以前 | 現在 |
|------|------|------|
| 新增／編輯／刪除交易後 | 要手動重整或切頁 | 自動更新總覽、持倉、紀錄 |
| 切換頁面 | 每次都重打 API | 5 分鐘內用快取，畫面瞬間出現 |
| 按刷新股價 | 丟背景任務，可能失敗且無感 | 同步等待（約 3–5 秒），完成後畫面更新 |
